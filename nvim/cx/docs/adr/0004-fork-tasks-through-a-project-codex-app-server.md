# Fork Tasks through a Project Codex app-server

Each Project runs an official Codex app-server on a Unix socket. Root Codex and every Task Codex connect to that server. When Root runs `cx task`, the Go CLI asks the owning app-server to fork the active Root thread, stores the returned child thread ID, and resumes that child inside the Task Neovim. The fork includes the persisted part of Root's active turn followed by an interrupted-turn marker. `cx` sends no new prompt, so the child waits for the user. Once the child terminal is ready, `cx` switches the current UI to the Task while the original buffer remains in the detached Root. If `cx` cannot reach the owning app-server or verify the Root thread, Task creation fails and removes its partial state rather than reading a possibly stale session from disk.
